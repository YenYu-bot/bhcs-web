# Pilot #1 光學與透鏡成像｜教學腳本 v1.3（審閱提案）

> 狀態：**PROPOSED / 不可直接實作或公開**。這是 v1.2 既有實作上的內容／UX 改善提案；維持 `assets/optics-guided/model.js` 的物理 oracle 與 `engine.js` 的已通過 state contracts。所有「新增介面」都屬建議，尚未寫入 production。
>
> 核心問題：**「為什麼移動物體後，原本清楚的投影會變模糊？為什麼有時怎麼移屏幕都無法聚焦？」**
>
> 原則：先看現象→操作→留下本人證據→比較→命名→公式；不以「猜答案」測驗當作入場前提，不提前洩漏理論像距；老師只提供下一個可操作指令與如何看變化。

## 0. 每位學生應學會

1. 指出「蠟燭／物體」「凸透鏡」「接像屏幕」三個實物；知道先移動屏幕尋找清晰影像。
2. 固定焦距與物體的位置時，能實際移屏幕並記錄自己看到最清楚的 **觀察位置**，不靠自動跳答案。
3. 固定凸透鏡，讓蠟燭向透鏡靠近但保持 `u>f`，能用兩組數據說出「清楚實像位置更遠、實像更大」。
4. 將蠟燭移至焦距內，認真檢查三個屏幕區域後知道屏幕接不到清楚實像；透過透鏡可看見正立放大的虛像。
5. 區分「實物、實像、虛像」「真光線、虛線延長線」「理論推算值、本人觀察值」；不把兩張照片或畫面當成兩個實物。

## 1. 全頁固定介面契約

- **桌機**：操作 bench 是視覺主體，右側余老師只顯示當前一件事；先看到三器材，卡片隨紀錄漸進出現。
- **手機 390px**：導航→余老師→實驗桌（可垂直捲頁）→清晰度狀態→當前 CTA→條件／紀錄。屏幕／蠟燭的 touch hit target 至少 44×44；不得水平捲頁。
- **新增微調操作建議**：僅對目前可動的器材出現「往左 1 cm」「往右 1 cm」兩個真按鈕，最小點擊面 44px；與 dragging、鍵盤都呼叫同一 engine 的 `MOVE_SCREEN` / `MOVE_CANDLE`，屏幕的每一步另依既有契約送 `SETTLE_SCREEN`。按鈕不暴露理論答案、不可一鍵跳至 sharp；拖曳仍是主要探索。
- **當前器材狀態**：只一項可動時強調其可操作輪廓，其他器材明確「固定」而非看起來壞掉；手機不依賴 hover。
- **回饋**：狀態同時文字＋圖形／清晰度，永不只靠顏色。主要指令每次不超過兩句；逐步提示不能先報 15、30 或「虛像」。
- **記錄一致性**：實驗 1/2 只有 sharp 且學生按「記錄」才寫入 `observedScreenPosition`；所有後續表格由 record 派生，不硬編碼 15／30。
- **自由探索**：主流程不放 slider；原 `tools/science/optics.html` 仍為獨立進階入口。不改模型、公式、焦距／範圍。

## 2. 從零開始的完整分鏡與余老師台詞

### S00｜Welcome：提出情境

- **畫面**：蠟燭、凸透鏡、屏幕的簡化靜態構圖，尚無答案。
- **余老師主句**：「投影的影像有時很清楚，有時很模糊。你知道差別在哪裡嗎？」
- **余老師副句**：「這次我們不用先記公式，直接在實驗桌找答案。」
- **CTA**：「開始實驗」→ `START`。
- **驗收**：不能先顯示 `v` 的數值、串聯／並聯等不相關名詞、虛像、公式，未操作時不提前宣布結果。

### S01｜Mission：認識器材

- **畫面**：`f=10, u=30, s=20`。屏幕是明顯模糊（Lv3），器材名稱小標籤（**蠟燭／透鏡／屏幕**）可辨認；屏幕是下一步唯一可動物件。
- **余老師主句**：「這支蠟燭的位置先不動。請移動右邊的屏幕，找出影像最清楚的位置。」
- **副句**：「注意看屏幕上的蠟燭影像，是越來越清楚，還是越來越模糊。」
- **CTA**：「動手試試看」→ `BEGIN`。
- **首次操作提示**：顯示一次「拖動屏幕，也可以用左右微調」；不可偷移屏幕，也不要畫出正確落點。

### S02｜Trial 1 find-screen：學生首次找清晰成像

- **條件**：`f=10,u=30` 固定，學生可動 `8≤s≤40`；初始 `s=20`，`theoreticalV=15` **內部真值不顯示**。
- **預設教師句**：「移動屏幕，看看影像的邊緣什麼時候最清楚。」
- **學生往錯方向移動**：「剛才影像反而更模糊了，試著往另一個方向找看看。」
- **接近清晰（Lv2）**：「影像邊緣比剛才清楚，快找到了。」
- **久無進展**：由已有 `hints` 行程距離觸發分級提示；最後一級可說「往左／往右試試」，方向依 engine oracle，**不說準確幾 cm**。
- **新增微調**：學生先實際探索後可按左右 1cm 步進；目前位置與狀態同步更新；微調不可調過鎖定範圍。
- **狀態與 CTA**：`trial1-find-screen → trial1-complete` 僅 sharp 時自動；「記錄第一次結果」只有 sharp 才可按。移出 sharp 後停用，無需倒退 phase。
- **科學值與回饋**：`u=30 → v=15,m=-0.5`，倒立縮小；手機 1cm snap 只有 `s=15` 合格，桌機可能 `14.5,15,15.5`。

### S03｜Trial 1 complete/record：讓觀察成為證據

- **余老師主句**：「這次的影像最清楚了。請把你找到的屏幕位置記下來。」
- **CTA**：「記錄第一次結果」→ 學生主動 `RECORD`。
- **紀錄表**：物距 = 30cm，清楚像距 = **本次實際 s**，影像方向 = 倒立，影像大小 = 較小。不得把理論 15 自動回填為實測值。
- **完成後**：「第一筆證據完成。接下來只改變蠟燭的位置。」→ `trial2-move-object`。

### S04｜Trial 2 move-object：只改一個變因

- **實驗控制**：透鏡焦距維持 10cm，屏幕先停在前次實際紀錄位置 `r1.observedScreenPosition`；只解鎖蠟燭。u 可在 12～35 變動，目標 u=15。
- **余老師主句**：「屏幕先不要動。把蠟燭從 30cm 移到 15cm，看看原來的影像會怎樣。」
- **過程觀察**：隨蠟燭移動即時失焦；`u=12` 的真實像距會超出 bench，狀態明確說「清楚位置超出這張實驗桌」，不得稱為虛像。
- **完成條件**：只有 `u=15` 自動 `trial2-find-screen`；不能提前接受其它位置為完成。
- **教學句**：「只改蠟燭的位置，原本清楚的屏幕位置就變模糊了。現在再移動屏幕試試。」

### S05｜Trial 2 find/complete/record：再次找清晰影像

- **起始**：`f=10,u=15`、`s=r1.observedScreenPosition`，應為 Lv4。
- **可動**：僅屏幕 s 8～40；最清楚處 `v=30,m=-2`。
- **提示**：「先留意影像大小，慢慢移屏幕找回清楚的邊緣。」**不提前說 30cm**。
- **sharp 後**：「第二次也找到了。這次影像的大小，和第一次一樣嗎？」
- **CTA**：「記錄第二次結果」；記錄此時 `observedScreenPosition`（含合法 29.5／30／30.5），並保留「倒立、較大」。
- **自動進入**：`compare`，沒有再寫入第三筆或改動第一筆。

### S06｜Compare：用真正的兩筆紀錄推論

- **余老師主句**：「把你自己找到的兩筆結果放在一起，看看只改變物距後，什麼跟著改變。」
- **比較表**（欄位為第一次／第二次）：
  - 焦距：10cm／10cm（控制變因）
  - 物距：30cm／15cm（唯一操縱變因）
  - 清楚像距：`r1.observedScreenPosition`／`r2.observedScreenPosition`（不是固定 15／30）
  - 像的大小：較小／較大（由 model record 派生）
  - 像的方向：倒立／倒立（新增建議，避免把大小變化看成方向翻轉）
- **學生回應兩問**：「蠟燭靠近透鏡後，清楚位置變得更近還是更遠？」「影像變大還是變小？」
- **不吻合時**：「先對照你紀錄的兩個清楚位置，以及蠟燭影像的大小。」不得給出答案選項的正確值。
- **成立後**：「只看這兩次實驗，蠟燭在仍能成清楚實像的範圍內靠近透鏡時，清楚位置變得更遠，影像也變大。」
- **CTA**：兩題由 record 驗證正確才解鎖「繼續」。

### S07｜Trial 3 move-object：靠近焦距內

- **過程**：`u=15 → 5`，蠟燭範圍放寬至 5～35；屏幕保持固定。移過 `u=10` 的焦點時，沒有 Infinity／NaN 或隱形跳躍；`u=10.5` 的屏幕外實像也不會被判為虛像。
- **余老師主句**：「那麼，再把蠟燭靠近一點，還能在屏幕上找到清楚影像嗎？請把蠟燭移到 5cm。」
- **副句**：「這次先不要急著下結論，等一下要再查三個不同距離。」
- **不設必答預測題**，避免先前教材被要求取消的預測門檻；思考問題只作引導。
- **達 5cm 時**自動進入 `trial3-search-screen`。

### S08｜Trial 3 search-screen：真正查三區（此次優先修正）

- **條件**：`f=10,u=5`，理論虛像 `v=-10`；右側屏幕全部 8～40cm 無 sharp。
- **余老師主句**：「請在屏幕的近處、中間、遠處各停下一次，看看有沒有清楚的影像。」
- **可見進度**：`已停下觀察：近處 □／中間 □／遠處 □`，依 `SETTLE_SCREEN` 填入 ✓；進度 `0/3` → `3/3`。不顯示理論像距。
- **區間**：近 `8≤s<17`，中 `17≤s<29`，遠 `29≤s≤40`；此區分是要求比較觀察位置，**不是**讓學生背界線。到達該區但未停下，不算一次完整觀察。
- **操作補救**：「剛才只是滑過中間，請在中間停一下再觀察。」僅在必要時出現，不代替動手操作。
- **第一／第二次 settle 回饋**：「近處已檢查，還差兩個位置」等，由已完成區產生，不把其他區標已完成。
- **三區皆完成**：「你已經檢查過三種距離，仍沒有清楚的影像。請用你的觀察做下一步判斷。」
- **CTA**：「已檢查近、中、遠，仍找不到清楚影像」只有 3/3 可按；學生按後才寫 Trial3 記錄、轉入 `trial3-no-real-screen-image`。
- **禁忌**：不能單次滑過整條軌道就算三區；也不能在沒有完成搜尋前直接告訴學生是「虛像」。

### S09｜No real screen image：形成問題，而非否定學生

- **余老師主句**：「你的三個位置都找過了，屏幕仍接不到清楚影像。」
- **副句**：「但是光線不一定消失了。試試從凸透鏡的另一側用眼睛觀察。」
- **CTA**：「從透鏡後面看」→ `VIEW_THROUGH_LENS`。
- **不要寫**「沒有光」「沒有像」「只是屏幕放得不夠遠」。

### S10｜View through lens：分清實物與虛像

- **畫面**：蠟燭實物以原樣顯示，放大且正立的虛像用半透明／虛線輪廓並清楚標示**「看到的影像（虛像）」**；小蠟燭標示**「實際蠟燭」**。從右側觀察的眼睛有文字圖例。
- **光線圖**：實線是實際傳播的光；若要表現眼睛認為影像來自哪裡，只用**虛線反向延長線**，不讓學生認為光真從虛像位置發出。
- **余老師主句**：「你看得到的是一個正立、放大的蠟燭影像。哪個才是實際的蠟燭？」
- **引導二選一（可只口頭，不必強制測驗）**：「實際蠟燭／看到的放大影像」；避免畫成兩個不加分辨的實物。
- **第一次 CTA**：「我觀察到了」，接著余老師命名「這種只能從透鏡看到、無法直接投到屏幕上的像，叫做虛像。」
- **第二次 CTA**：「比較這兩種像」→ `concept`。此前實驗1/2 的名詞仍暫緩呈現。

### S11｜Concept：用學生結果解釋實像與虛像

- **證據卡**：實像可投影、光線確實會合；虛像的光線未在影像看起來的地方真正會合，不能直接投到屏幕。
- **先對照學生自己的** `observedScreenPosition`，然後才揭露理論公式：
  `1/f = 1/u + 1/v`；`m=-v/u`。
  - 第一次 `f10,u30→v15,m-0.5`：實像、倒立縮小
  - 第二次 `f10,u15→v30,m-2`：實像、倒立放大
  - 第三次 `f10,u5→v-10,m+2`：虛像、正立放大
- **說明**：「負的像距不表示屏幕真的要移到負的位置，而是表示這次的影像位在物側，不能被右側的屏幕直接接到。」
- **模型限制**：理想薄凸透鏡；不納入像差、實際透鏡厚度、真實投影亮度與環境照明。
- **CTA**：「進入研究手冊」。

### S12｜Notebook A／B／C：留下自己的說法

- **Level A 幫我整理（預設）**：兩句自動填入實際 `r1/r2` 的物距／清楚像距，學生選「影像位置更遠」「影像變大」；應與記錄一致才可進下一步，不可由固定理論值判斷。
- **Level B 自己說**：開放敘述，以自己兩筆數字解釋變化；目前系統只檢查非空，**畫面明示並非內容正確性自動評分**。
- **Level C 研究員挑戰**：回答資料支持什麼、還不能推論什麼（例如只有兩組資料不能證明所有物距都如此）；輸入完成後才能展開參考思考點；非空不等於老師驗證正確。
- **CTA**：「進入挑戰題」，依各 Level 已有 gate。未記錄過的第三輪不應虛構實測像距。

### S13–S15｜三題遷移挑戰

1. **影像突然模糊**：只移屏幕；余老師問「哪個條件被改過？」；不要在第一次回答錯時直接報答案。
2. **蠟燭在 8cm／焦距 10cm**：屏幕能否接到？從透鏡後方觀察是什麼樣子？不要求心算像距，回到第三輪證據。
3. **放大鏡看文字**：文字位於焦距內時，眼睛看得到正立放大字，但白紙無法接到清楚像；應能連結虛像概念。
- 依原 `CHALLENGES` 順序解鎖；答錯第一次指回證據，第二次提供非洩漏的提示；只有實際按選項才計入次數。第三題可選擇寫自己的話，不能強迫輸入才算完成。

### S16｜Complete：總結與離站

- **學生可見**：「你完成了三輪實驗，找到兩個清楚實像，並發現另一種只能用眼睛透過透鏡看的虛像。」
- **總結由本人資料驅動**：「我把物距從 r1.u 改成 r2.u，屏幕清楚位置從 r1.observed 變成 r2.observed。當物體靠近凸透鏡、仍能成實像時，像距增加且影像變大。」
- **入口**：「自由探索／精確數值」→ 既有 `tools/science/optics.html`。重來應明確要求確認，避免清除已存 notebook。
- **不聲稱**已完成老師批改或真實光學器材操作訓練。

## 3. 特殊操作與提示對照

| 狀況 | 合理訊息 | 禁止誤導 |
|---|---|---|
| 拖蠟燭經 `u=f` | 「光線幾乎平行，這時在有限距離的屏幕找不到聚焦點。」（可等 Concept 再用正式詞彙） | Infinity / NaN、顯示清楚實像或說「沒有光」 |
| `u>f` 但 `v>40` | 「會形成實像，但清楚位置超出實驗桌。」 | 說是虛像或把屏幕誤判 sharp |
| 屏幕從 sharp 移出 | CTA 停用，提示「回到最清楚的位置再記錄」 | 偷記最後的正確位置 |
| 手指放開尚未 sharp | 保留現在位置，可用微調繼續 | 自動吸附清楚位置 |
| 第三輪滑過三區但只在一區停下 | 僅該區打勾，提示到其它區**停下觀察** | 三區自動通過 |
| 虛像標示 | 「實物」和「看到的虛像」清楚分辨 | 兩蠟燭皆像真實物件 |
| B／C 輸入「好」 | 可觸發既有非空機制，但提示「系統未批改內容」 | 宣稱內容必定符合科學推理 |

## 4. 本輪不得變更的內容

`f/u/v/m`、t=0.75 及清晰度 oracle；`PHASES` 的順序、find→complete 自動、complete→recorded CTA、三區 `SETTLE_SCREEN` 判定、record 的 observed/theoretical 分離、Challenge 判定與儲存 schema、v1.1 共用元件契約，都保持原樣。新增的手機微調／進度呈現應是既有 engine action 的 UI adapter，**不是第二套成像公式或捷徑判定**。
