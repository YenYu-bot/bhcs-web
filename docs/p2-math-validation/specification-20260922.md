# 驗收規格修訂｜2026-09-22

來源：本輪使用者指示，優先於原交接包。使用者明確更正：「200 題全部不重複」是交接包 2.4 的規格誤寫。2.2 一直要求「同一份卷內不重複」，有限 8 題的題庫本來就合理。

### 2.4 每一項的驗收（修訂）
對每個 unit × 難度 × mode：
1. 測試以 `safeQuestion()`（含 50 次重試）為單位，連續抽樣 200 次；各次使用新的 seen，單卷去重另依第 2 條驗收。斷言：每次都拿到題目（重試耗盡才算失敗）、`verify()` 全過、無例外。`gen()` 回傳 null 是拒絕訊號，不算失敗，但記錄每組的拒絕率；拒絕率超過 50% 的 unit 另列「效率警示」表，不阻擋合併，留給後續調範圍時參考。重試內的例外與 verify false 仍記錄並列待修，不讓 safeQuestion 的攔截掩蓋原有錯誤。
2. 模擬一份卷：以該 unit 在介面上允許的最大題數抽題，卷內 `sig` 不得重複。
3. 題庫有限的 unit 必須在程式裡宣告 `bankSize`。測試改為：200 次抽樣的相異 `sig` 數＝`bankSize`（全題覆蓋），且卷內不重複只要求到 `bankSize` 為止。**未宣告 `bankSize` 卻在 50 次內產生不出新題的，仍算失敗**——這才是真的有問題。
4. 保留原教材的數字範圍與題型，修正只能針對錯誤，不得順手調整難度或改寫題目。
