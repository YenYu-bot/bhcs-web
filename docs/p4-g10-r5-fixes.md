# r5：依 ChatGPT 閘門報告（2026-09-23）修正 r3／r4 的問題

r5 ＝ r4（七個 topic）＋以下修正。用 r5 整包覆蓋 #45。

| 閘門回報 | 根因 | 修正 |
|---|---|---|
| `inequalities/quadratic` 挑戰：−x²＋6x−18 ≤ 0 答「無解」（26 次 verify false） | 解集合建構函式在「沒有零點」時取試值點 `b−1`，b 為 +∞ → NaN → 判成空集 | 無零點時試值改取 0。八種（開口正負 × 四符號）逐一確認：正確給出「無解」或「所有實數」 |
| `inequalities/always` 挑戰：`無效分數`（18 次例外） | k 同時在兩個係數的題型，先用 R() 建構 −pq/4 再檢查是否整數，非整數時 R() 已拋錯 | 先檢查 (−pq) % 4，不整除直接 return null |
| `linecircle/tangent` 進階／挑戰：`無效分數`（359 次例外） | 切線長題型先用 R() 建構 u·d/w，再檢查是否整數 | 先算 u·d/w 與 v·d/w，非整數 return null 再建構 |
| P3：`inequalities/linear` 基礎 52→44 | 基礎級只留原本一種形式 | 基礎級 25% 出「兩邊都有 x」；本機 92 |
| P3：`quadratic/discriminant` 進階 25→23 | 進階只有兩種 kind | 進階加入「兩交點的 k 範圍」；本機 28 |
| P3：`linecircle/minmax` 基礎 7→6 | 基礎級我把 r≥d（點在圓內）排除掉，原版沒有 | 基礎級恢復允許，不加註解；本機 7 |
| P3：`linecircle/chord` 基礎結構數 2 | 基礎只有「求弦長」「反求距離」 | 加入「給直徑」的形式；本機 3 |

閘門抓到的三個例外都是同一類錯誤：**用 R() 建構之後才檢查整數**。我的本機檢查器原本只走 `safeQuestion()`，而它會吞掉例外重試，所以看不到。檢查器已改為同時直接呼叫 `gen()` 統計原始例外與原始 verify 失敗，並改成逐數型、每 40 題一份卷去重——與 ChatGPT 閘門的口徑一致。改完後七個 topic 在這個口徑下全部 PASS。
