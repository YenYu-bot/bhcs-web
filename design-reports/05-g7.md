# g7-drills.html design review (chunk 05: ratio, function, numberline, coordinate, lineeq, statistics, symmetry, views)

Source reviewed: `/home/claude/yenyu-bot/bhcs-web/tools/math/g7-drills.html` (branch `fix/math-answer-errors`), plus the 8 sampled topics in the chunk.

## Summary

1. **Curriculum (P1):** `topic=function` is 國二下 content under 108課綱 (F-8-1 一次函數 / F-8-2 一次函數圖形, 康軒 2下 第2章). On a 國一 page it is mislabeled; `quadraticValue`/`quadraticCoeff` are 國三下, and `piecewise`/`replaceFunction`/`composite`/`nested` are not in the 國中 curriculum at all. The page's own `levels` text admits this, yet the **challenge preset still auto-selects piecewise, quadraticCoeff, replaceFunction, composite, nested**. Meanwhile what a 國二 一次函數 unit actually tests (判斷是否為函數, 對應表/圖, 畫 y＝ax＋b 圖形, 應用題) is entirely absent.
2. **Structural ladder weakness (P1):** every function unit is `kinds[5]` with a sliding window (basic = kinds 0–2, advanced = 1–3, challenge = 2–4), so adjacent levels share 2/3 of their question forms and "challenge" frequently emits trivial items (`設 f(x)＝x，求 f(−2)×f(4)`). Number-line/coordinate/lineeq/statistics/symmetry/views units use a similar 3-kinds-per-level scheme but with hand-picked kind lists, which works better.
3. **Ratio (P1):** no 應用題 whatsoever (比例尺、按比例分配、濃度、速率、連比分配) — the heart of the 國一下 比與比例式 chapter. Also the three number modes are **identical** for pv/ev/re/cv/ca/cp-advanced (all integer coefficients regardless of mode); several ladder inversions (ch/cp basic-fraction is harder than advanced-integer); a duplicate-sub-question bug in pv; `genExprValue` (求 2b²/(4a²＋bc)) exists only inside mx and is not selectable.
4. **Ladder inversions outside ratio (P1/P2):** `mark` challenge uses smaller numbers than basic (max 3 vs 5 → "標出 A(−3)、B(3)" as challenge); `absval` advanced emits `｜3｜＝？`; `online` challenge is 7/8 the same trivial kind (通過原點求 k, answer = the constant); `count` list kind always answers "和為 0".
5. **Missing standard textbook types:** 圓形圖/直方圖 (statistics), 平行/重合 ⇔ 無解/無限多解 (lineeq), 立體圖→三視圖 and 三視圖→立體圖 (views; everything is from a numbered 俯視圖), 去絕對值 given sign (numberline), 比例尺/分配 word problems (ratio).
6. Mode design is mostly meaningful for numberline/coordinate/lineeq/statistics; it is cosmetic or empty for ratio (pv, ev, re, cv, ca), quadrant, and function-decimal (ugly 3-decimal answers like −8.876, 4.096 that no 國中 teacher would set).
7. Wording/notation polish needed in ratio answers: `x=7r÷1、y=27r÷3`, `1r=9`, `64r^2−1r^2`, `(−19):(−18)` kept before reducing, and `求：x:y=？` vs the answer giving 比值.

Priorities below: P1 = teacher/student would notice as wrong, confusing or clearly mis-levelled; P2 = clear quality gain; P3 = polish.

## Topic: ratio — 比例

- Levels promised: basic「整數與簡單單位換算的比值、繁分數、x 在一項的比例式、一個比的比值、簡單連比與連比例式」; advanced「分數小數與負數…含 x 一次式的比例式、兩個比的比值、方程式求比值、係數化的連比、連比活用三種」; challenge「複名數與百分位小數、兩邊都是一次式的比例式、平方項的比值、(x＋y)：(x−y) 條件、ax：by：cz、連乘積型連比、含常數項的連比求值」.
- Overall: computationally rich but purely symbolic. The whole topic has zero word problems, and the number mode is wired as `CFGR.types=[mode]` but most generators never read it, so 分數/小數 mode is a no-op for 6 of 11 units. Challenge is mostly "uglier numbers" (比值 109/81, 連比 242:364:143) rather than harder reasoning.

### Unit rv 比與比值（含單位換算）
- Variety: 2 kinds (bare a:b, unit-conversion a:b) at all levels; challenge adds 複名數 (`1m25cm:48cm`). No 最簡整數比, no 反求 (已知比值求前項/後項), no 判斷 (哪些比相等). Contexts: none (no objects).
- Difficulty: basic ok; advanced = negatives + decimals; challenge = 2-decimal numbers (`2.18:1.62`→109/81, `1.37:3.88`→137/388) — bigger arithmetic, not harder concept. Negative ratios (`(−23):12`) are unusual for 國一 textbooks (比的前後項 are positive quantities in 康軒/翰林); keep only in advanced/challenge if at all.
- Plausibility/tip/mode: tip ok. Fraction mode fine; decimal challenge produces non-textbook numbers. `(−22):6=−(22)/(6)=−(11)/(3)` fine.
- Proposed changes:
  1. [P1] Add kind 「化為最簡整數比」 (all levels; this is the first thing the textbook asks): `將 0.6：(3)/(4) 化為最簡整數比。` → `12：15＝4：5`; with units at basic: `45 分鐘：1(1)/(2) 小時 化為最簡整數比`.
  2. [P1] Add 反求 kind (advanced/challenge): `已知 x：12 的比值是 (3)/(4)，求 x。`, `已知 (2)/(3)：y＝4：9，求 y。`
  3. [P2] Add 應用/判斷 kind (basic/advanced): `甲班 30 人、乙班 25 人，甲乙兩班人數的比值是多少？`; `下列哪些比與 2：3 相等？① 4：6 ② 6：4 ③ 0.4：0.6 ④ (1)/(2)：(3)/(4)`.
  4. [P2] Challenge decimals: cap at one decimal place or force a terminating/simplifiable ratio (e.g. generate as k·(p:q) with p,q≤12) so answers stay like 7/5, not 331/275.
  5. [P3] Drop negative ratios from basic; in advanced limit to one negative term.

### Unit cx 繁分數化簡
- Variety: 1 form (a stacked fraction with integer/fraction/mixed/decimal top & bottom) with 3 phrasings (`＝？`, `求 … 的值`, `a÷b＝`). Challenge phrasing `951÷2=` (= 9 over 5½ written as "5 1÷2") in the text dump; check the printed HTML renders the mixed number clearly.
- Difficulty: basic/advanced/challenge differ only by number form (frac→mixed→2-decimal). Ok as a drill, but challenge `(1)/(4)÷1.34` is pure arithmetic.
- Plausibility/tip/mode: tip ok. Mode has no visible effect (basic-decimal gave `(8)/(9)/(1)/(7)`; basic-fraction gave `3.4/7.8`): the `forms` list ignores mode. Answer steps like `1×43×1=43` are a dump artefact of nested fraction HTML; fine on paper.
- Proposed changes:
  1. [P2] Make mode meaningful: fraction mode → only frac/mixed parts; decimal mode → at least one decimal part; integer mode → one integer part.
  2. [P2] Add a 3-layer 繁分數 kind for challenge (`1 / (1 + 1/2)`, `2 / (3 − 1/(1+1/3))`), which is what 參考書 challenge pages use, instead of 2-decimal numbers.
  3. [P3] Unify phrasing: use `化簡下列繁分數` once in the tip and show only the fraction (drop `求 … 的值` variant).

### Unit px 比例式求 x
- Variety: basic has 2 kinds (x alone; `(2x−5):(x+2)=1:2` type — this second kind already appears in **basic** fraction/decimal samples, e.g. `(3x+2):(−144)=1:9`, contradicting the levels text "x 在一項"); advanced = linear expressions on one side; challenge = linear on both sides, with fraction/decimal coefficients.
- Difficulty: ladder mostly holds. Basic-fraction `(3)/(4):(4)/(3)x=1:5` is harder than basic-integer. Challenge-fraction `((1)/(7)x+(6)/(7)):((4)/(7)x−(3)/(4))=8:7` is beyond any 國一 exam.
- Plausibility/tip/mode: tip ok; "外項乘積＝內項乘積" wording correct. Mode works.
- Proposed changes:
  1. [P1] Gate the linear-expression kind out of basic (keep basic = x alone, integers; e.g. `x:18=40:45`), matching the levels text.
  2. [P2] Add 應用 kind (advanced): `某班男女生人數比為 5：4，男生 30 人，女生幾人？`; `地圖比例尺 1：25000，圖上 4 cm 代表實際幾公尺？`
  3. [P2] Challenge: limit to one fractional coefficient per side (`((1)/(2)x−1):(x+3)=2:5`) and answers that are integers or simple fractions.
  4. [P3] Add "判斷 x 是否滿足" kind: `x＝4 是不是 (x＋2)：3＝8：4 的解？`

### Unit pv 比例式求比值
- Variety: 1 kind (x:y given, find ratio of linear combos), advanced asks 2 sub-questions, challenge adds a squared pair `(x²+3y²):(2x²+3y²)`. Two phrasings (`設/已知`, `除以`).
- Difficulty: fine, but challenge squared items give results like 313/434, 307/145 — set a,b ≤ 5 so they reduce.
- Plausibility/tip/mode: **Bug:** sub-questions can be identical (`① (−4x):y ② (−4x):y`, challenge decimal sample) — dedupe `sub`. Mode is a no-op (all three modes produce identical integer problems). Answer writes `1r^2`, `64r^2−1r^2`; and keeps `(−19):(−18)` before `19/18` (fine but add `=19:18`).
- Proposed changes:
  1. [P1] Dedupe sub-questions; reject when both (p,q,r,s) tuples match.
  2. [P1] Either remove fraction/decimal modes for this unit (`modes:["integer"]`) or make them real: fraction mode → `x:y=(1)/(2):(2)/(3)`; decimal mode → `x:y=1.5:2`.
  3. [P2] Add reverse kind (advanced/challenge): `已知 (x+y):(x−y)=5:3，求 x:y。` (now only inside `re`), and `已知 (2x−y):(x+y)=1:4，求 x:y 的比值`.
  4. [P3] Fix `1r²` → `r²`, cap squared-kind a,b ≤ 5.

### Unit ev 方程式求比值
- Variety: 1 kind (ax+by=cx+dy → x:y), advanced/challenge add a second sub-question. **Challenge ≡ advanced** (code uses `lvl>=2` only).
- Difficulty: basic forces same-sign ratio; fine. No real challenge.
- Plausibility/tip/mode: question says `求：x:y=？` but answer gives `x:y 的比值`; wording should be `求 x：y 的比值`. Mode no-op.
- Proposed changes:
  1. [P1] Give challenge its own kinds: (a) two equations in three unknowns → `已知 x+2y−3z=0，2x−y+z=0，求 x:y:z`; (b) fraction form `(x)/(3)=(y)/(5)`→ratio; (c) `3(x−y)=2(x+y)` bracket form.
  2. [P2] Wording: `已知 x、y 均不為 0，且 5x＋11y＝10x−7y，求 x：y 的比值。`
  3. [P3] Restrict modes to integer.

### Unit re 比例式與方程式求值
- Variety: basic = `x:y=a:b` + one equation → x,y; advanced adds `x:3y=7:27` normalisation and `(x−3):(y−7)` follow-up; challenge uses `(x+y):(x−y)=p:q`. Good coverage of the textbook type.
- Difficulty: ok, but numbers inflate (`9x+3y=1755`, `5x+8y=1184`) — cap r≤9 and coefficients ≤7. `3x:3y=4:1` and `2x:2y=3:2` are silly (equal coefficients).
- Plausibility/tip/mode: answer notation `x=7r÷1、y=27r÷3` and `1r=9` is not how a teacher writes it. Mode no-op.
- Proposed changes:
  1. [P1] Rewrite the normalisation step: `x：3y＝7：27 ⇒ x：y＝7：9（3y 對應 27，y 對應 9）`; never print `÷1`, `1r`.
  2. [P2] Exclude k1===k2 in advanced; cap constants.
  3. [P2] Add 應用 kind: `甲乙兩人存款比為 3：5，兩人共 2400 元，各多少元？`（basic）; `…甲比乙少 600 元`（advanced）.
  4. [P3] Integer mode only.

### Unit ch 連比
- Variety: 2 kinds (merge two ratios sharing a letter; `2x:3y:4z=8:13:18`→x:y:z). The alignment table in the answer (`a:b:c897556:63:40` in the dump) is an HTML table — fine on paper.
- Difficulty: **inverted across modes**: basic-fraction/decimal (`x:z=(1)/(3):0.8，y:z=0.8:0.75`, answers 242:364:143, 171:152:176) are much harder than advanced-integer (`x:y=1:2，y:z=4:1`). Challenge is just more of the advanced kind.
- Plausibility/tip/mode: tip "共用的量用最小公倍數對齊" ok. Decimal mode answers (242:364:143) are unrealistic — a textbook never has three-digit 連比.
- Proposed changes:
  1. [P1] Basic in every mode: shared term already equal or small LCM (≤12), answer terms ≤ 30; move decimal/fraction ratios to advanced with answers ≤ 60.
  2. [P2] Challenge: add `a:b=2:3，b:c=4:5，c:d=…` four-term chains and the "x:y=…, x:z=… , 求 (x+y):z" follow-up.
  3. [P3] Reject any result with a term > 100.

### Unit cp 連比例式求 x、y
- Variety: 1 kind (solve two unknown terms), challenge sometimes adds `與 x＋y`.
- Difficulty: inverted — basic-fraction `(5)/(6):0.25:(2)/(3)=x:y:1` vs challenge-integer `14:2:14=x:2:y` (trivial) and `x:1.5:y=3:1:4`. Challenge-fraction `2(1)/(3):0.625:1(2)/(3)=1(5)/(9):x:y` is absurd for 國一.
- Plausibility/tip/mode: fine otherwise.
- Proposed changes:
  1. [P1] Re-level: basic = integer ratios with one given integer term; advanced = one decimal/fraction term; challenge = unknown in the *given* side (`x:8:y=3:4:5` with x+y asked) or 應用 (`三人分 1800 元，比為 2：3：4，各得多少？`).
  2. [P2] Reject degenerate proportions (two equal terms like `14:2:14`, `13:12:13`).

### Unit ca 連比活用
- Variety: 3 kinds (`3a=7b=6c`, `a/4=b/7=c/6`, `2x:3y=…,y:2z=…`), challenge adds `4ab=6bc=2ac` and `ab:bc:ca=…`. Good.
- Difficulty: ladder ok. Basic-decimal/fraction identical to integer (mode no-op).
- Plausibility/tip/mode: tip 「先化成 x：y、y：z 等兩兩的比再合併」 does not match the `3a=7b=6c` method used in the answer (設 r). Mode no-op.
- Proposed changes:
  1. [P2] Tip: `等式型（3a＝7b＝6c）令等式＝r；分式型令每個分式＝r；兩個比則先化成 x：y、y：z 再合併。`
  2. [P3] Integer mode only.

### Unit cv 連比與求值
- Variety: basic = `a:b:c` + one condition; advanced = two ratios/equation `9x=5y` first; challenge adds `(a−5):(b+3):(c+6)` follow-up. Good.
- Difficulty: ok. Decimal ratios like `b:c=19.8:3.3` (advanced/challenge) only add arithmetic.
- Plausibility/tip/mode: `1r=17` notation again. Mode: fraction/decimal only changes the given ratio form — acceptable.
- Proposed changes:
  1. [P2] Add 應用 kind at every level: `三角形三內角比為 2：3：4，求最大角。`（basic）; `長方體長寬高比 3：2：1，所有稜長和 48，求體積`（challenge）.
  2. [P3] `1r`→`r`.

### Unit mx 綜合練習
- Variety: random pick of the 11 generators plus `genExprValue` (`a=4b，b=2c，求 2b²/(4a²+bc)`) and `genChainRatioValue` (`x:y:z=…→(−x+y−z):(−3x−2y−3z)`), neither of which is a selectable unit.
- Difficulty: inherits level; fine.
- Proposed changes:
  1. [P2] Expose `genChainRatioValue` as its own unit (連比求比值) — it is a standard type; keep `genExprValue` challenge-only (squared fraction is 參考書 extra).
  2. [P3] Tip "綜合練習。" is empty — list which skills are mixed.

## Topic: function — 函數

- Levels promised: basic「直接代入求一次、常數函數值與簡單運算；由兩個函數值反求一次函數」; advanced「兩個函數值、函數值的差與倍數、兩式相等反求、f(0) 與 f(k) 反求…連續函數值總和」; challenge「函數值的增量、f(x＋1)−f(x)、分段端點與巢狀分段、f(k)＋f(k＋1)、和差反求、f(x＋s) 替換、g(f(g(x)))、f(f(k)) 反求」.
- Overall: **108課綱 places 函數 in 國二下 (F-8-1, F-8-2)**; this page should either move the topic to the g8 page or label it 「國二預習」. Of the 12 units, 6 are outside the 國中 curriculum (page admits it) yet are in the challenge preset. The remaining 6 cover only "plug in and compute" — nothing on what the chapter actually assesses: 判斷對應關係是否為函數, 由表格/圖形讀函數值, 畫一次/常數函數圖形, 圖形與兩軸交點, 應用題 (計程車、彈簧、水位). Every unit shares the `kinds[5]` sliding window, so levels overlap heavily. Decimal mode routinely yields 3-decimal answers (−8.876, −68.348) — not textbook.

### Unit linearValue 一次函數值
- Variety: 5 kinds (f(k); y＝ax＋b 當 x＝ 時; f(a) 與 f(b); f(0),f(1),f(1)−f(0); 增量). Basic/advanced/challenge each see 3 of them.
- Difficulty: challenge `設 f(x)＝−x＋1，求 f(0)、f(1)…` is basic-level; challenge-integer coefficients are the same size as basic.
- Plausibility/tip/mode: decimal basic `f(−2.1)＝−13.56` is unrealistic; fraction basic `f((1)/(5))＝−(123)/(50)` likewise. Tip fine.
- Proposed changes:
  1. [P1] Challenge: only 增量 kind + a new 「f(x＋1)−f(x)」 kind (`設 f(x)＝3x−2，求 f(x＋1)−f(x)`) + table kind (`完成函數值表：x＝−2,−1,0,1,2`); never the plain f(k).
  2. [P2] Decimal mode: coefficient 1-decimal, input integer (`f(x)＝0.5x＋1.2，求 f(4)`); fraction mode: input integer or input with denominator dividing the coefficient's.
  3. [P2] Add 應用 kind (basic/advanced): `計程車起跳 85 元，每公里加 20 元，車資 f(x)＝20x＋85，求搭 6 公里的車資。`

### Unit quadraticValue 二次函數值（進階）
- Variety: 3 forms (f(k), y 當 x＝, f(a) 與 f(b), f(a)±f(b)).
- Difficulty/curriculum: 國三下 content (F-9-1). Decimal mode gives `−8.876`, `31.439`.
- Proposed changes:
  1. [P1] Keep hidden by default (already) and remove from the challenge preset path; mark 「國三」 in the unit name, not 「進階」.
  2. [P3] Decimal mode: integer inputs only.

### Unit constantValue 常數函數
- Variety: 3 kinds (f(big number); f(a)+g(b); f(1)+…+f(n); f(a)×f(b)). The `f(−4)＋f(1)−f(116)` form is cute but the 116 looks random.
- Difficulty: flat; it is a one-idea unit. Challenge `f(1)＋f(2)＋⋯＋f(24)` is fine.
- Proposed changes:
  1. [P2] Add graph/judgement kinds: `常數函數 y＝−3 的圖形是水平線還是鉛直線？與 y 軸交於哪一點？`; `下列哪一個是常數函數？① y＝5 ② y＝5x ③ x＝5`.
  2. [P3] Use numbers like 100/2024 instead of 116/145 for the "any x" message.

### Unit combinedValue 函數值綜合運算
- Variety: f(a)±f(b), f(a)×f(b), pf(a)−qf(b), f(a)÷f(b). Near-duplicate of linearValue advanced.
- Difficulty: challenge `設 f(x)＝x，求 f(−2)×f(4)` is trivial; decimal `f(−4)×f(5)＝−416.15` is pointless.
- Proposed changes:
  1. [P1] Challenge: require |a|≥2 and b≠0, and add `f(a)·f(b)＝?` only with integer results; or merge this unit into linearValue and free the slot for 「函數的判斷」.
  2. [P2] New unit 「函數的判斷與對應」 (basic): `下列對應關係哪些是函數？① 每個學生對應他的身高 ② 每個正數對應它的平方根（正負兩個）…`; table→rule kind: `x：1,2,3,4；y：3,5,7,9，寫出 y 與 x 的關係式`.

### Unit piecewise 分段函數（進階）
- Variety: 2-piece with linear/quadratic right piece; challenge f(f(k)).
- Curriculum: not in 國中. Also the right piece often contains x² (國三).
- Proposed changes:
  1. [P1] Remove from the challenge preset; if kept, restrict both pieces to linear.

### Unit solveInput 由函數值反求輸入
- Variety: f(k)=v; f(k)=g(k); y 當 y＝ 時 x; f(2k)/f(3k)=v; f(k)+f(k+1)=v. Good set.
- Difficulty: ladder ok. Decimal `f(k)＝−13.53` style is contrived (fine at challenge, not basic).
- Proposed changes:
  1. [P2] Add graph-reading version (advanced): `一次函數圖形通過 (2, 5) 與 (4, 9)，當 y＝13 時 x＝？`
  2. [P3] Decimal basic: targets with ≤1 decimal.

### Unit linearCoeff 反求一次函數係數
- Variety: two values; two points; f(0)&f(k); difference+value; sum&difference. Good.
- Difficulty: challenge `f(0)＝−5、f(2)＝5` is basic-level (kind 2 leaks into challenge via the window).
- Proposed changes:
  1. [P1] Challenge window should exclude kind 2 (f(0) form); add kind: `一次函數 y＝ax＋b 的圖形通過 (1,4)，且 f(3)−f(1)＝6，求 a、b` and 「與 y＝2x＋3 平行且過 (1,−1)」(國二 range).
  2. [P2] Add 應用 kind: `彈簧原長 b 公分，每掛 1 公斤伸長 a 公分；掛 2 公斤長 14 公分、掛 5 公斤長 20 公分，求 a、b。`

### Unit quadraticCoeff 反求二次函數係數（進階）
- 國三 content. Fine as an optional extra; remove from challenge preset. [P1]

### Unit replaceFunction 函數替換（進階）
- Not in 國中 curriculum (g(x−4)＝f(2x−2)). Keep optional; remove from challenge preset. [P1] Tip is good.

### Unit composite 複合函數（進階）
- High-school content. Keep optional; remove from challenge preset. [P1]

### Unit sumValues 連續函數值總和
- Variety: 5 kinds; tip is long but correct. Challenge uses x² forms (國三).
- Difficulty: challenge `f(1)＋f(3)＋f(5)` with f(x)＝x−1 is easy; fine otherwise.
- Proposed changes:
  1. [P2] Keep this as a 國二 extension; in challenge prefer odd-term sums with n≥5 and the symmetric `f(−n)…f(n)` trick; drop the x² kind unless 國三.

### Unit nested 巢狀函數值（進階）
- Not in curriculum. Optional; remove from challenge preset. [P1]

## Topic: numberline — 數線與絕對值

- Levels promised: basic「整數；讀數線、標點、比較大小、求絕對值、兩點距離、｜x｜＝k」; advanced「分數與小數；刻度 0.5、0.25…；中點、｜x−a｜＝k、含絕對值的除法與混合運算」; challenge「多數排序、已知距離求點、哪一點較近；a＜｜x｜≦b 的整數、列出整數；巢狀絕對值與已知兩數絕對值求 a＋b」.
- Overall: solid 國一上 coverage with figures; the main defects are level inversions in `mark`/`absval` and missing 去絕對值 (符號判斷) items.

### Unit mark 數線上的點
- Variety: read / plot / between (basic, advanced) ; read / plot / shift (challenge). Figures good.
- Difficulty: **inverted** — `max` is 5/4/3 for basic/advanced/challenge, so challenge-integer emits `標出 A（−3）、B（3）`, `A（3）、B（1）`; the shift kind is plain addition. Advanced only adds a third letter.
- Plausibility/tip/mode: tip ok; fraction/decimal modes are meaningful (刻度 0.25, 1/3).
- Proposed changes:
  1. [P1] max per level 5/8/10; challenge-integer must use a scale with 一小格＝2 or 5 (`每一小格代表 5`) or unlabeled origin (`已知 A 表示 −2、B 表示 4，寫出 C 的數`).
  2. [P2] Add kinds: 「中點/對稱點」(`A(−3)、B 是 A 對原點的對稱點…`), 「由兩點推刻度」(`A＝1，B＝7，相鄰刻度間隔多少？C 表示多少？`).
  3. [P3] `between` answer should list the integers only when ≤6.

### Unit compare 正負數的大小比較
- Variety: two/negs/zero → two/negs/mixed(分數 vs 小數) → order/negs/between. Fine.
- Difficulty: basic-fraction `−(43)/(4) □ −(22)/(3)` is harder than advanced-integer `−9 □ −2`. Challenge `between` answers "例如 (169)/(60)" — ugly.
- Proposed changes:
  1. [P1] Basic-fraction: same denominator or denominators 2/3/4 with |n|<10; move unlike-denominator comparison to advanced.
  2. [P2] Add 判斷/符號 kind for challenge: `若 a＜0＜b 且 ｜a｜＞｜b｜，將 a、−a、b、−b 由小到大排列。`
  3. [P3] `between`: produce a "nice" example (nearest half/integer), not the mean.

### Unit absval 絕對值
- Variety: abs/negabs/opp → abs/negabs/inner → inner/nested/same.
- Difficulty: **advanced-integer emits `｜3｜＝？`, `｜10｜＝？`** (max shrinks 20→12 and kinds overlap); basic already has `−｜−11｜`.
- Proposed changes:
  1. [P1] Advanced: drop plain `abs`; use inner/negabs/opp-with-expression.
  2. [P1] Add 去絕對值 kind (advanced/challenge) — a must-have 國一 type: `若 a＜0，化簡 ｜a｜＋a`; `若 x＜3，化簡 ｜x−3｜`.
  3. [P2] Add 判斷 kind: `｜a｜＝−a，則 a 是什麼數？`

### Unit distance 數線上兩點的距離
- Variety: two/origin/fig → two/fig/mid → find/mid/closer. Good; midpoint and "B 可能表示什麼數" are the right challenge items.
- Difficulty: fine; basic-fraction `(26)/(3)、(5)/(4)` → 89/12 is heavy for basic.
- Proposed changes:
  1. [P2] Basic-fraction: like denominators. Add kind 「已知中點與一端求另一端」(challenge): `M(−1) 是 AB 中點，A(3)，求 B。`
  2. [P3] Add 應用 wording variant: `溫度計上 −3℃ 與 8℃ 相差幾度？`

### Unit absinv 已知絕對值求原數
- Variety: good (basic/none/zero → basic/shift/plus → shift/plus/both). `both` (a＞b) is the right challenge.
- Difficulty: basic-decimal gives `｜x｜＝−5.3` four times out of 8 — the `none` kind is over-sampled; otherwise ok.
- Proposed changes:
  1. [P2] Weight `none` to ≤1 per sheet. Add challenge kind `｜x−1｜＋｜y＋2｜＝0，求 x＋y`.

### Unit count 滿足絕對值條件的整數
- Variety: lt/le/neg/pos → lt/le/ring|frac → combo|frac/ring/list.
- Difficulty: fine. `list` always answers 「和為 0」 (symmetric range) — students learn the trick once and stop computing.
- Proposed changes:
  1. [P1] `list`: use asymmetric conditions (`｜x｜＜5 且 x＞−2`, `−3≦x＜4`) so the sum is non-zero; or ask `它們的和與積`.
  2. [P2] Add `｜x−2｜＜3 的整數` (shifted) for challenge.

### Unit absarith 含絕對值的四則運算
- Variety: add/sub/mul → add/sub/div/mix → mix/inner/nested. Good.
- Difficulty: fine. Fraction basic `−｜(7)/(3)｜×｜−(25)/(3)｜＝−175/9` is heavy.
- Proposed changes:
  1. [P2] Basic-fraction: products that simplify (e.g. 3/4 × 8/9).
  2. [P3] Add 「比較大小」 variant: `比較 ｜−3｜−｜−5｜ 與 ｜−3−(−5)｜`.

## Topic: coordinate — 直角坐標

- Levels promised: basic「讀點、描點、坐標軸上的點、判斷象限、點到兩軸距離、平移、水平鉛直線特徵、長方形面積」; advanced「由象限與距離求點、符號推理判斷象限、移動方式、軸上相距 d 的點、三角形、平行四邊形」; challenge「A(a−p, b+q) 推象限、絕對值和為 0 求點、含參數的點與距離、正方形頂點與中點、外包法、由面積反求點」.
- Overall: good 國一下 coverage; the ladder holds. Issues are mode relevance (quadrant), overlap between axisdist and translate, and a few missing standard types (對稱點 is in symmetry topic — fine).

### Unit readpt 讀出點的坐標與描點
- Variety: read/plot/axis → read/plot/swap → read/plot/sum. Good.
- Difficulty: challenge `圖中各點的 x 坐標總和為 a… 求 a−b` is a nice twist; `swap` in advanced is a judgement item (good).
- Proposed changes:
  1. [P3] `swap`: when P and Q fall in the same quadrant the answer「P 在第一象限，Q 在第一象限」reads oddly — prefer pairs in different quadrants.
  2. [P3] Add 「連點成圖形」 kind (basic): `描出 A(−2,1)、B(3,1)、C(3,4)、D(−2,4) 並依序連接，是什麼圖形？`

### Unit quadrant 象限的判別
- Variety: num/axis/list → sign/given/list → shift/absz/given. Good.
- Difficulty: ladder ok; `｜x＋6｜＋｜2x−y＋1｜＝0` is a proper challenge.
- Plausibility/tip/mode: fraction/decimal modes only change the given coordinates to fractions — pointless for a sign question. 
- Proposed changes:
  1. [P2] `modes:["integer"]` for this unit (or let fraction mode generate `(−(1)/(2), 0.3)` type at most).
  2. [P3] Add 「點 (a, b) 在第二象限，則 a＋b、ab 的正負？」 kind (advanced).

### Unit axisdist 點到兩軸的距離
- Variety: both/nearest/walk → fromq/walk/nearest → param/twice/equal. `walk` (向北走… 求 B 與到兩軸距離) duplicates translate's kinds.
- Difficulty: ok; challenge `P(3+a, −1−a) 在第二象限且到 y 軸距離 5` is good.
- Proposed changes:
  1. [P2] Replace `walk` with 「到 x 軸距離 3、到 y 軸距離 2 的點有幾個？寫出坐標」(4 answers) — the classic textbook item.
  2. [P3] Add 面積 link: `P(−4, 3) 與兩軸、原點圍成的長方形面積`.

### Unit translate 平移與方位
- Variety: go/howto/vh → howto/go2/axisline → square/mid/center (integer only). Good; midpoint and square kinds are proper challenge.
- Difficulty: ok.
- Proposed changes:
  1. [P2] Add 「連續移動後回原點」 kind: `P 向東 3、向北 2、再向西 5，到 (−1, 4)，求 P。`
  2. [P3] `square` wording「依順時針 A→D→C→B 排列」is confusing; say「A、B、C、D 依逆時針順序」and add a sketch.

### Unit area 坐標平面上的面積
- Variety: rect4/tri0/rectA → tri0/triAxis/para → wrap/wrap/findpt. Good; 外包法 at challenge is right.
- Difficulty: fine.
- Proposed changes:
  1. [P2] Challenge `wrap` answer should show the subtraction (`7×9−½·…`) not just「外包長方形 7×9」.
  2. [P3] Add 「四邊形面積 (梯形)」 kind at advanced.

### Unit hvline 水平線與鉛直線

### Unit graph 畫圖形與通過的象限

### Unit twopoint 由兩點求直線方程式

- Difficulty: ok. Note 「求通過兩點的直線方程式」 via 聯立 is textbook-acceptable in 國一下; `(−3t, −2t−5)` 參數式 is 參考書-level, fine for challenge.

## Topic: statistics — 統計圖表與資料分析

- Levels promised: basic「5–8 筆整數資料；次數分配表、平均數、奇偶筆中位數、眾數、讀長條圖」; advanced「分組次數分配表、基準數算平均、次數表求中位數；加入或刪去一筆後的平均；折線圖」; challenge「百分比與累積人數、組中點平均、由中位數反求 x；三者一起求；加入後平均與中位數同時變化；兩組合併與兩筆未知資料」.
- Overall: thorough on 平均/中位/眾數; weak on 圖表 (only 長條/折線; no 圓形圖, 直方圖, 次數分配折線圖 which 108 D-7-1 lists). Decimal mode ("平均數可為小數") is well-defined. Table rendering is HTML (fine on paper).

### Unit freq 次數分配表
- Variety: simple/count/most → group/simple/most → group/relative/cum. Good.
- Difficulty: ok. Context limited to 閱讀本數/投籃/家中人數/數學成績.
- Proposed changes:
  1. [P2] Add 直方圖 kind (challenge): draw the histogram from the grouped table, or 「依直方圖回答 70 分以上有幾人」.

### Unit mean 算術平均數
- Variety: raw/table/two → raw/table/dev → table/dev/group. Good; 基準數 and 組中點 are the right advanced/challenge items.
- Difficulty: ok. `two` (甲組 4 人、乙組 4 人) always equal sizes at basic — then the answer is just the mean of means; include unequal sizes at advanced.
- Proposed changes:
  1. [P2] `two` with unequal sizes at advanced (`甲 4 人平均 16，乙 6 人平均 21`), which forces the weighted method.

### Unit median 中位數
- Variety: odd/even/sortfirst → odd/even/table → table/unknown/even. Good.
- Difficulty: ok. Note basic-integer gives pre-sorted lists for odd counts (`9、14、16、…`) — sorting practice lost.
- Proposed changes:
  1. [P2] Shuffle data in basic too (keep `sortfirst` as the explicit sorting kind).
  2. [P3] `unknown` (已知中位數反求 x) — also an odd-count version where x is the middle.

### Unit mode 眾數
- Variety: one/table/word → one/two/table → two/none/compare. Good; "沒有眾數" and "兩個眾數" handled.
- Proposed changes:
  1. [P3] `compare` kind should sometimes ask which of 平均/中位/眾數 best represents the data (判斷題), e.g. with one outlier.

### Unit chart 長條圖與折線圖
- Variety: max/diff/total → diff/total/avg → avg/change/ratio. All numeric reads; no 圓形圖, no "依表畫圖".
- Difficulty: ok.
- Proposed changes:
  1. [P1] Add 圓形圖 kind (percent → count, count → 圓心角): `圓形圖中「籃球社」占 25%，全校 480 人，籃球社幾人？圓心角幾度？`
  2. [P2] Add 「依次數分配表畫長條圖/折線圖」 (student draws; answer figure in 教用版).
  3. [P3] Decimal mode currently indistinguishable from integer in this unit.

### Unit change 加入或刪去一筆資料
- Variety: addMean/delMean/same → addMean/delMean/addMedian → addMedian/delMedian/addBoth. Good.
- Difficulty: ok.
- Proposed changes:
  1. [P3] `same` kind (加入等於平均數的資料) appears 4/8 in basic-integer — cap at 1.

### Unit missing 已知平均數求缺漏的資料
- Variety: one/exam/need → one/need/after → after/group/two. Good.
- Difficulty: ok; `need` (至少要考幾分) and `group` are good.
