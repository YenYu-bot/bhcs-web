## Summary
Overall: the 13 topics cover the computational core of 國二 math well. The geometry pages (angles through construction) and quadapps have explicit per-level kind lists, true-angle figures and good challenge items. The weaknesses come in four groups:

1. **Structural ladder bug in sqrt and pythagoras** (L1281, L1406). These two topics account for 26 of the 87 units. `mkUnit` picks the kinds with a sliding window `[0,1,2]/[1,2,3]/[2,3,4]`, and the number ranges ignore the level. Wherever the kind order is not easy→hard, the ladder comes out inverted. Examples: conjugate basic `(5√10 − 6√11)^2` while the easy `(7＋√11)(7−√11)` appears only above basic; simplify basic `√1815` vs challenge `√4 × √3`; ladders `長 111 公尺的梯子`. arithseq and quadsolve use the same window but suffer less.
2. **Bugs teachers will notice (P1)**:
   - Impossible data: `samebase.trap2` builds trapezoids with inconsistent areas. `construction.value.perpTri` gives `AC＝30、BC＝3` with D between B and C.
   - Ambiguous MC: in `construction.basis`, two or three options are correct.
   - Duplicates: `parallel.names.count` and `judge.three` print the same question twice on one sheet (random sig, constant text).
   - Display:
     - `x(x)＝9` (quadsolve cross)
     - `AB＝4x＋0`, `(1x＋30)°`, `(1x＋53)°` (congruence, quadrilateral)
     - `2∠A－4∠B＝-60°` and the `BC−PB → -1` answers (ASCII minus)
     - `aₙ＝−5×(3)/(2)ⁿ⁻¹` (no parentheses around a fractional ratio)
     - `化簡：1（…）`
     - addRadicals challenge shows `12√10` where an unsimplified radical was intended.
   - Redundant givens: altitude (height given but not needed) and geoseq twoterms (a₁ given, then asked for).
3. **Curriculum fit**:
   - 根與係數 (α＋β、αβ、α²＋β²) is not in the 108 國中 curriculum but appears at quadsolve **basic**.
   - 樞紐定理 and the 圓/弦/圓心角 wording (triineq, congruence) need checking against the three textbooks.
   - numberLine in pythagoras is mostly 國一 review.
   - 填空式說理 for 全等 is absent, although 108 requires 說明理由.
4. **Missing standard question types** (the biggest content gaps):
   - arithseq: **no 應用題** at all.
   - quadapps: no 成長率 or 無蓋紙盒.
   - pythagoras: no 畢氏逆定理判別, 摺紙 or 最短路徑.
   - angles and parallel figure staples: 8 字形, 飛鏢形, 鉛筆形, 紙條摺疊, 光線反射.
   - bisectors: no 等腰三角形分類討論.
   - quadrilateral: no 三角形兩邊中點連線.
   - construction: no 三角形作圖 or 特殊角作圖.
5. **Mode and plausibility**:
   - sqrt decimal mode puts decimal coefficients on radicals (`1.365√130`), which is not textbook style. Restrict decimal mode to the units where decimals sit inside the root.
   - Answers use the form `(1)/(15)√255` instead of `√255⁄15`.
   - Implausible contexts: 社團人數 ×3/2 every year; 長方形 with equal sides; unreduced ratios (`6：6：6`, `4：4`).

## Topic: sqrt — 平方根 (`sqrtConfig` L1257–1392)
- Levels promised: basic「平方根的意義、正平方根、√(a²)、最簡根式、估算、簡記、根式乘除與有理化、同類方根、共軛根式、雙根號分母有理化」; advanced「負平方根、兩根號加減、代入求 √((x−c)²)…三個根式相乘、連除、根式平方…」; challenge「兩平方根的和與積…整數與小數部分、比大小、括號內的加減…奇數項連鎖與反求 n」.
- Overall: 14 units × 5 kinds each. **Structural problem (all 14 units):** `mkUnit` (L1281–1284) picks kinds by a sliding window `[[0,1,2],[1,2,3],[2,3,4]]`, and the number ranges (`pv/sv/sf`) do NOT depend on level. So (a) basic and advanced share 2 of 3 kinds, advanced and challenge share 2 of 3; (b) whenever the kind order in the array is not easiest→hardest, the ladder inverts (see conjugate, simplify, principalRoot); (c) "challenge" is never bigger/harder numbers. Second structural problem: **answer display** `Eh()` (L1274) writes `(1)/(15)√255`, `−√5 ＋ √10`, `(4)/(11)√2 ＋ (4)/(11)√13` — Taiwanese textbooks write √255⁄15, √10−√5, 4(√13＋√2)⁄11 or (4√13＋4√2)⁄11. Third: **decimal (and partly fraction) mode is unnatural for radical operations** (`1.365√130`, `(2.6√6 ＋ 1.1√13)^2 → 56.29 ＋ 5.72√78`); textbooks use decimals only inside the root (√0.09, √1.44, √0.5).
- Global proposed changes for this topic:
  1. [P1] Replace the sliding window with an explicit per-level kind list per unit (e.g. `levels:{basic:[0,1],advanced:[1,2,3],challenge:[3,4]}`) and pass `Lv` into the number pickers so basic uses small radicands/coefficients (k≤4, coefficient 1–3) and challenge uses larger or multi-step ones. Reorder kinds so index order = difficulty (fixes for conjugate/simplify/principalRoot below).
  2. [P1] Answer format: (i) when the result is a single term c·√d with c a fraction p/q, print as fraction with radical in numerator: `√255⁄15`, `2√66⁄11`, `−4√19⁄19`; (ii) for multi-term results, put a positive term first (`√10 − √5`, `2√3 − 2`, `3 − √3`) instead of ordering by radicand; (iii) for multi-term with common denominator, print `(4√13 ＋ 4√2)⁄11` (or `4(√13＋√2)⁄11`) rather than separate fractions. Implement in `Eh` with a "textbook" flag used for answers.
  3. [P1] Decimal mode: restrict to units where decimals are natural — rootMeaning, principalRoot, absoluteRoot (√0.0144、√1.69、−√0.25), estimate (「√0.5 的近似值」、「√2.25 與 1.4 比大小」) and add a kind 「把 √0.08 化成最簡根式（＝(√2)⁄5）」 to simplify. For notation, multiplyRadicals, divideRadicals, rationalize, addRadicals, conjugate, binomialDenominator, mixed, telescoping set `modes:["integer","fraction"]`. Fraction mode in operation units should put fractions **inside** the root (√(3/8), √(2/3)) or use simple coefficients like ½√8, not (5/3)√13 everywhere.

### Unit rootMeaning 平方根的意義
- Variety: 5 kinds (平方根、x²＝a、負數有無平方根、負平方根、p＋q 與 pq). Basic gets 3; 「負數有沒有平方根」 is 1/3 of basic and the answer is always identical — 4 of 8 fraction-basic samples were `−(196)/(25) 有沒有平方根？`. Missing standard types: non-perfect squares (「求 7 的平方根」→ ±√7), 0 的平方根, 「√81 的平方根」 trap (→ ±3), 「a 的平方根是 2m−1 與 m−5，求 a」 (classic 反求), 判斷題 「(−3)² 的平方根是 −3」.
- Difficulty: advanced/challenge only add 負平方根 and p＋q／pq — p＋q＝0, pq＝−a is a one-liner, not challenge.
- Proposed changes:
  1. [P1] Cap the 「有沒有平方根」 kind at ≤1 per page and move it to a 判斷 kind with mixed statements: 「下列敘述對嗎？(1) −16 的平方根是 −4 (2) 0 的平方根是 0 (3) 7 的平方根是 ±√7」.
  2. [P2] Basic: add 「求 13 的平方根」→ `±√13`; 「求 0 的平方根」.
  3. [P2] Challenge: replace p＋q／pq with 「若一正數的兩個平方根是 2a−1 與 a−5，求 a 與這個正數。」(a＝2，正數 9) and 「√81 的平方根是多少？」(±3).

### Unit principalRoot 正平方根
- Variety: 5 kinds, all 「求值：±√(n²) (±√…)」. Challenge sample `求值：√1 ÷ √16` is easier than basic `√484`. Ladder flat/inverted.
- Missing: 「√√16」, 「√(4×25)」, 「√(1 7/9)」 (帶分數化假分數, fraction mode), 「√0.36」 (decimal).
- Proposed changes:
  1. [P2] Challenge kinds: 「求值：√(4 ×81)」, 「求值：√(1 (9)/(16))」→ 5/4 (fraction mode, 帶分數), 「求值：√√256」→4, 「求值：√(3²＋4²)」→5 (vs 3＋4 trap).
  2. [P3] Avoid √1 and divisor √1 (`√1 ÷ √16`).

### Unit absoluteRoot 根號與絕對值
- Variety: 5 kinds; fine coverage of √(a²)＝|a|. Challenge is 7/8 「當 x＝… 時求 √(x−c)²」 which is a numeric substitution (advanced-level).
- Missing: 「若 2＜x＜5，化簡 √((x−2)²) ＋ √((x−5)²)」 (→3) — the standard 會考 type; 「若 √((a−3)²)＝3−a，求 a 的範圍」.
- Proposed changes:
  1. [P2] Challenge: add 「若 2＜x＜5，化簡 √((x−2)²) ＋ √((x−5)²)。」 and 「若 √((x−4)²)＝4−x，x 的範圍為何？」(x≦4). Drop the substitution kind from challenge.
  2. [P3] Render `√(7)^2` as √(7²) or √7² consistently — `√(−16)^2` is ambiguous in print if the overline is lost.

### Unit simplify 最簡根式
- Variety: 5 kinds. Ladder inverted: kind 1 (`rand(4,12)`) puts `√1815 → 11√15`, `√756` in **basic**, while challenge (kinds 2–4) yields `化簡：√4 × √3`, `√18 × √18` (trivial). Also `√4 × √3` duplicates multiplyRadicals.
- Proposed changes:
  1. [P1] Basic: k∈2–5, d∈{2,3,5,6,7} (√12, √50, √75, √98); advanced: k up to 12 and coefficient outside (`3√99`); challenge: fraction radicand (`√(2/3)`), `√(0.08)`/`√(1/8)` (fraction/decimal mode), and 「√(180n) 為整數，最小正整數 n＝？」 (classic → 5).
  2. [P1] Remove kind 3 (`√x × √y`) from this unit (it is multiplyRadicals).

### Unit estimate 根號估算
- Variety: 5 kinds; ok in basic/advanced. Mode ignored entirely (fraction/decimal produce integer questions). Challenge 「比較 3√3 與 3√5」 has equal coefficients — trivial; tip says 逐位試算 but only "到小數第二位" asked with no method.
- Missing standard types: 「最接近 √n 的整數」, 「a＜√n＜a＋1 的正整數 n 有幾個」, 「5 − √7 的整數部分與小數部分」, 「√n 介於 6 與 7 之間，n 可能是哪些整數」, 「√2 ≈ 1.414，求 √200、√0.02」.
- Proposed changes:
  1. [P2] Challenge: 「求 5 − √7 的整數部分 a 與小數部分 b」(a＝2，b＝3−√7); 「已知 √2≈1.414，求 √0.02、√200 的近似值」; 「滿足 3＜√n＜5 的正整數 n 有幾個？」(15).
  2. [P2] Comparison kind: force a≠c and pick pairs that are close (e.g. 4√3 vs 3√5) so the comparison is not visible by eye.
  3. [P3] Mode: decimal mode → 「√0.5 介於哪兩個 0.1 位數之間」 or mark unit integer-only.

### Unit notation 根式簡記
- Variety: 5 kinds, mostly (a)×(b√d). Samples include `(−5√11) × (1)` and inconsistent brackets `(6) × 5√10`. Answer `−(1)/(3)√11` should be `−√11⁄3`.
- Proposed changes:
  1. [P2] Exclude ±1 multipliers; always bracket negatives only (`6 × 5√10`, `(−2√3) × (−6)`).
  2. [P2] Promote 「把 5√11 寫成 √n」 (kind 4, currently challenge-only) to basic/advanced and add the reverse 「√275 寫成 a√b」 is simplify — fine. Add 「比較 2√7 與 3√3（移入根號）」 here if estimate's version is removed.

### Unit multiplyRadicals 根式乘法
- Variety: 5 kinds. Basic includes 3-factor products (`(−√3)(2√13)(−√10) → 2√390`) though levels text says 三個根式相乘 is advanced; products of random SF radicands often don't simplify (`√70`, `√390`, `√154`) so there is no 化簡 skill exercised.
- Proposed changes:
  1. [P1] Basic: √a×√b where ab has a square factor (√6×√10＝2√15, √3×√12＝6) — choose y=x·k²/… so ≥70% simplify. Move 3-factor to advanced.
  2. [P2] Challenge: 「(√12 − √3)√3」, 「√2(√8 ＋ √18)」 (simplify-then-distribute).

### Unit conjugate 共軛根式與根式平方
- Variety: 5 kinds. Ladder inverted: the easiest kind (`(7 ＋ √11)(7 − √11)`, kind 3) is never in basic, while basic has `(5√10 − 6√11)^2 → 646 − 60√110`. Coefficients up to 6 at every level.
- Proposed changes:
  1. [P1] Reorder: basic = (a＋√d)(a−√d), (√a＋√b)(√a−√b) with coefficient 1, (√a＋1)²; advanced = coefficients ≤3, (√a±√b)²; challenge = (A＋B)²−(A−B)², and 「(√3＋√2)¹⁰(√3−√2)¹⁰」→1 (指數律配共軛).
  2. [P2] Decimal mode off (see global 3).

### Unit binomialDenominator 雙根號分母有理化
- Variety: 5 kinds; good ladder. Answers `(4)/(11)√2 ＋ (4)/(11)√13` should be `(4√13 ＋ 4√2)⁄11`.
- Proposed changes:
  1. [P2] Answer format (global 2). Prefer a−b dividing c in basic (`4/(√7−√3)` → √7＋√3) so basic answers are clean.
  2. [P3] Challenge: add 「x＝1/(√3−√2)，求 x＋1/x」.

### Unit mixed 根式綜合
- Variety: 5 kinds. Kind 2 multiplies two random binomials with unrelated radicands → 4-term junk at basic/advanced (`(4√2 ＋ 3√11)(2√10 − √3) → 16√5 − 4√6 − 3√33 ＋ 6√110`). Challenge 5/8 samples are the same 「設 a＝√x＋√y、b＝√x−√y，求 a²＋b² 與 ab」.
- Proposed changes:
  1. [P1] Kind 2: draw both binomials from the same two radicands (`(4√2 ＋ 3√5)(4√5 − 3√2) → 36 ＋ 7√10`, which already appears when radicands coincide).
  2. [P2] Challenge: vary the symmetric expression: a²−ab＋b², (a−b)², a/b＋b/a, a²b＋ab²; and 「x＝√3＋1，求 x²−2x＋5」 (代值配方, 會考 type).

### Unit telescoping 連鎖有理化
- Variety: 5 kinds; ok. `化簡：1（…）` shows coefficient 1 (kind 2, `pv(m,5)` can be 1). Uses `√1` instead of 1. Mode irrelevant. This is 補充 material; fine as challenge, but basic/advanced levels exist.

## Topic: pythagoras — 畢氏定理與兩點距離 (`pythagorasConfig` L1394–1510)
- Levels promised: basic「由兩邊求第三邊、根式斜邊、矩形對角線、數線與水平垂直距離、坐標兩點距離、反求一個坐標」; advanced「等腰三角形的高、正方形與正三角形、斜邊上的高、梯子與行走距離…」; challenge「兩股比與和、正三角形面積、斜邊的分段、長方體對角線、梯子下滑、竹子折斷、數線分點、判斷直角、等距點、周長與對角線求面積、菱形」.
- Overall: same sliding-window `mkUnit` as sqrt (L1406–1409) → ladder is "which kinds", never "harder numbers"; number size is identical (or larger) at basic. Triples come from a 10-item list `TR` scaled ×1–3 in integer mode, producing implausible contexts (`一把長 111 公尺的梯子`) and big numbers at basic (`A(2，0)、(38，105)`). Figures appear only in kind 0 of hypotenuse/leg/radicalSide/composite, so advanced/challenge are almost figure-free. Missing standard 8上 types across the topic: **三邊判斷直角三角形（畢氏定理逆敘述，S-8-6 明列）**, 正方形面積圖（三個正方形）, 摺紙（矩形摺疊求長）, 長方體表面最短路徑（螞蟻）, 數線上的根式點（√2 作圖判讀）.
- Global proposed changes:
  1. [P1] Level-dependent scale: basic `k=1` only and triples from {3-4-5, 6-8-10, 5-12-13, 8-15-17}; advanced adds 7-24-25, 9-12-15, 20-21-29, 9-40-41; challenge adds 12-35-37, 11-60-61, 28-45-53, 33-56-65 and k up to 3. Replace the sliding window with explicit per-level kind lists (as in sqrt).
  2. [P1] Context-scaled numbers: ladder lengths 2.5–10 m (use decimal triples 1.5-2-2.5, 3-4-5, 2.4-0.7-2.5, 6-8-10), walking distances in 公尺 up to a few hundred (fine), 竹子 ≤ 10 m. Never ×3 on a 37-unit triple in a ladder.
  3. [P2] New unit or kinds 「直角三角形的判別」: basic 「三邊長為 9、12、15 的三角形是直角三角形嗎？」; advanced 「三邊長 √2、√3、√5」、「三邊長 7、24、26」; challenge 「三邊長 a²−1、2a、a²＋1」 with a given.
  4. [P2] Add figure-based kinds at advanced/challenge: 「如圖，三個正方形圍成直角三角形，面積分別為 25 與 144，求第三個正方形面積」; 「長方形紙 ABCD，AB＝8、BC＝10，沿 AE 摺使 D 落在 BC 上的 F，求 CE」(challenge, 會考 classic); 「長方體 3×4×12，螞蟻沿表面由 A 爬到 G 的最短距離」.

### Unit hypotenuse 求斜邊
- Variety: 5 kinds; basic mixes figure, text, 等腰直角. Challenge 「一股長為 3 的等腰直角三角形」 also appears at basic (kind 2 is in all three windows) — challenge not harder. Decimal mode `4.9√2` fine.

  2. [P3] `直角三角形兩股長的比為 12：35，斜邊長為 111` → cap scale at ×2 for large ratios.

### Unit radicalSide 根式邊長
- Variety: 5 kinds; advanced 5/8 samples are 「正方形的邊長為 25，求對角線長」 (kind 2 in all windows; answer is just 25√2 — no simplification exercised). Challenge 「正三角形的邊長為 29，求它的高」 → 29√3⁄2 fine.

### Unit altitude 斜邊上的高
- Variety: 5 kinds. **Kind 2 gives redundant data**: `直角三角形的斜邊長 87，斜邊上的高為 (1260)/(29)，一股長 60，求另一股長` — b follows from c and a; the height is noise and its ugly fraction appears at **basic**.
